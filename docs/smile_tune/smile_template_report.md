# 스마일(치아 노출) / 치아 템플릿 / 템플릿+프롬프트 조합 실험

FLUX.2 Klein 4B(4 step)로 만든 합성 얼굴 112장에서, 새 실험용 스타일 `smile_final_smile_v3.yaml`의 스마일(치아 노출 정도) control과
치아 템플릿 이미지(`patient_tooth`)의 효과를 비교했다. 모든 호출은 실제 HTTP API(`/api/v1/infer`)로 했다.

- 환경: RTX 4090 1장, `design_tune_server.py` 기본 설정(fp8 가중치 저장 + bf16 연산, compile 없음), seed 0, 요청당 1.7~2.6초
- 지표
  - 스마일 = MediaPipe blendshape `mouthSmileLeft/Right` 평균, 입 벌림 = `jawOpen` (0~1)
  - 윗니/아랫니 노출 = `teeth` 마스크(밝기 규칙)를 안쪽 입술 중심선(랜드마크 13·14) 위/아래로 나눈 면적, 얼굴 폭² 대비 ×1000. **대략적인 근사치**다
  - 치아 밝기 L*, 노란기 b* = `teeth` 마스크의 LAB 평균 (b*가 클수록 노랗다)
  - 신원 = ArcFace(InsightFace buffalo_l) 코사인 유사도. 원본에서 얼굴이 잡힌 101명 기준
  - 입 영역 차이 = 원본 `mouth` 마스크(dilate 16) 안의 평균 절대 차이 (0~255)

## 요약

- **치아 노출 control은 "입 다물기(0)"만 확실하고, "아랫니까지 보이기(100)"는 절반쯤, "윗니만 보이기(75)"는 거의 안 된다.**
  - 0: 112명 모두 치아가 사라진다. 대신 아래 얼굴을 크게 다시 그려 신원이 0.71로 떨어진다.
  - 100: 윗니만 보이던 얼굴의 42~45%에서 턱이 벌어지고 아랫니가 더 드러난다.
  - 75: 이미 아랫니가 보이는 얼굴에서 아랫니를 가린 경우가 19%뿐이다.
- **원인은 마스크가 아니라 문장이다.** 처음 문장("윗니만 보이는 미소")은 마스크를 넓히거나 없애도 원본과 같았다.
  "아랫입술을 내려 아랫니를 드러내라"처럼 동작을 지시하는 문장으로 바꾼 뒤에야 100이 움직였다.
- **템플릿만으로도(프롬프트 없이) 미백·정렬된 치아가 나온다.** 다만 프롬프트만 쓴 결과와 거의 같아서, 템플릿의 "모양"이 따라온다고 보기는 어렵다.
  프롬프트만 쓴 결과와 템플릿을 더한 결과의 차이(14.9)가 seed만 바꾼 차이(13.5)와 비슷하다.
- **템플릿+프롬프트 조합은 프롬프트만 쓸 때보다 이점이 없다.** ArcFace 점수는 0.92 → 0.87로 떨어지지만, 얼굴 전체로 보면 같은 사람이다
  (4.1절). 점수 차이는 입술색·치아 모양 차이에서 온다. 템플릿의 분홍 입술색이 환자 입술로 번지는 문제가 있어 미백/정렬은
  **`patient_only` + 프롬프트를 권장**한다.
  단, smile 100에서는 아랫니가 보이는 템플릿이 아랫니 노출을 조금 늘렸다(아랫니 면적 9.9 → 11.6).

## 2. 스마일(치아 노출 정도)

### 2.1 smile_final_smile_v3.yaml

v2(`smile_final_smile.yaml`)의 상대 표현("더 작게 웃게")은 무표정 얼굴에서 반대로 동작했다([mice_smile_report.md](mice_smile_report.md) 2.3).
v3는 **"치아가 얼마나 보이는지"를 절대 표현**으로 정했다. 50(유지) 문장에는 `smile` 단어를 넣지 않았다.

| 값 | 의도 | preset |
| --- | --- | --- |
| 0 | 입 다문 무표정, 치아 안 보임 | `smile_closed` |
| 25 | 입 다문 미소 | `smile_closed_lip` |
| 50 | 원본 유지 | `natural` |
| 75 | 윗니만 보이는 미소 (아랫입술이 아랫니를 덮음) | `smile_upper` |
| 100 | 윗니+아랫니가 모두 보이는 큰 미소 | `smile_full` |

최종 조합 preset(pose 제외)으로 `smile_upper_align_whiten`(75 + 정렬 100 + 미백 75), `smile_full_align_whiten`(100 + 정렬 100 + 미백 75)을 추가했다.
마스크는 입꼬리·볼이 움직여야 하므로 아래 얼굴(`mouth` + `cheeks`, dilate 24, feather 16) inpaint를 썼다.

### 2.2 첫 문장의 실패: 상태 묘사로는 바뀌지 않는다

처음 75/100은 "윗니만 보이는 미소", "윗니와 아랫니가 모두 잘 보이는 미소"처럼 **결과 상태**를 묘사했다.
현재 샘플(`my/samples/medit/image.png`)에서 마스크를 넓혀도(dilate 48, 얼굴 전체), **마스크를 없애도** 원본과 거의 같았다
(jawOpen 0.12 → 0.13~0.14). 따라서 마스크 범위가 아니라 문장 문제다.

"아랫입술이 올라와 아랫니를 완전히 덮게", "턱을 더 벌리고 아랫입술을 내려 아랫니 줄을 드러내게"처럼 **동작**을 지시하는 문장으로 바꿨다.
이후 100이 움직이기 시작했다(아래 2.3).

![현재 샘플 빠른 테스트](assets/smile_v3_medit.jpg)

현재 샘플에서 0과 25는 의도대로 동작했다(jawOpen 0.00, 25는 입 다문 미소 smile 0.84).

### 2.3 112명 결과

표정 그룹별 평균 (스마일 / jawOpen / 윗니 면적 / 아랫니 면적):

| 그룹 | 원본 | 0 (closed) | 75 (upper) | 100 (full) |
| --- | --- | --- | --- | --- |
| 윗니만 보이던 얼굴 (60) | 0.84 / 0.13 / 12.5 / 6.4 | 0.13 / 0.01 / 0.1 / 0.0 | 0.88 / 0.12 / 12.1 / 6.3 | 0.90 / **0.17** / **15.1** / **7.8** |
| 아랫니도 보이던 얼굴 (52) | 0.93 / 0.24 / 19.5 / 10.2 | 0.14 / 0.06 / 0.1 / 0.0 | 0.93 / 0.20 / 16.5 / **8.8** | 0.94 / 0.26 / 19.6 / 9.4 |

| 판정 | 결과 |
| --- | --- |
| 0: 치아가 사라짐 (윗니+아랫니 면적 < 0.5) | **112/112 (100%)** |
| 0: smile < 0.2 이고 jawOpen < 0.05 | 58% (나머지는 입은 다물었지만 입꼬리가 살짝 올라감) |
| 100: 윗니만 보이던 얼굴에서 jawOpen +0.03 이상 / 아랫니 면적 ×1.3 이상 | 45% / 42% |
| 75: 아랫니도 보이던 얼굴에서 아랫니 면적 ×0.7 이하 | **19%** |
| 신원 (0 / 75 / 100) | **0.71** / 0.93 / 0.93 |

![치아 노출 비교](assets/smile_v3_exposure.jpg)

- **0은 안정적이지만 신원 손실이 크다.** 웃는 얼굴을 무표정으로 바꾸려면 아래 얼굴 전체를 다시 그려야 해서 신원이 0.71까지 떨어진다(최저 0.51).
- **100은 절반 정도에서 동작한다.** 위 그림 face_033, face_055, face_075, face_001에서 아랫니가 새로 드러났다.
  이미 아랫니가 보이는 얼굴에는 거의 변화가 없다(더 벌릴 여지가 적다).
- **75는 거의 동작하지 않는다.** 아랫니를 가리려면 아랫입술을 올려야 하는데, 이미 벌어진 입을 오므리는 방향의 변화가 모델에서 약하다.
- 75/100 단독 preset(정렬·미백 0)에서도 치아가 일부 고쳐진다(face_000의 착색이 줄어듦). 입을 다시 그리면서 생기는 부수 효과다.

## 3. 템플릿 실험 (템플릿만 vs 프롬프트만)

같은 얼굴, 같은 seed에서 비교했다. 템플릿은 얼굴마다 `upper` 템플릿 10장을 순서대로 배정했다.

- **프롬프트만 (PO):** `patient_only` + `smile_upper_align_whiten`
- **템플릿만 (PT):** `patient_tooth` + 영역 지시문 `teeth_from_template`("치아를 image 2의 모양·배열로 바꿔라") inpaint. 스마일·정렬·미백 문장 없음
- **seed 1:** PO를 seed만 바꿔 다시 생성한 것. 템플릿 효과가 우연한 변동보다 큰지 보는 기준선

| | 치아 L* | 노란기 b* | 신원 | 원본 대비 입 영역 차이 |
| --- | --- | --- | --- | --- |
| 원본 | 77.7 | 14.3 | - | - |
| 프롬프트만 (PO) | 84.8 | **0.8** | 0.92 | 19.2 |
| 템플릿만 (PT) | **85.4** | 3.3 | 0.92 | 20.0 |

| 비교 | 입 영역 차이 |
| --- | --- |
| PO seed 0 vs PO seed 1 (seed 변동) | 13.5 |
| PO vs PT(프롬프트+템플릿) (템플릿 효과) | 14.9 |
| 템플릿 효과 > seed 변동인 얼굴 | 63% |

![템플릿 비교](assets/smile_v3_template.jpg)

- **템플릿만으로도 미백·정렬 효과는 프롬프트와 비슷하다.** 템플릿 치아가 희고 가지런하기 때문이다. 노란기는 프롬프트가 더 확실히 뺀다(b* 0.8 vs 3.3).
  - 가장 노란 그룹(`yellow`, `yellow_crooked`)의 b*: 24~26 → PO −0.7~−1.3, 템플릿만 2.2~5.1
- **템플릿의 치아 "모양"이 결과에 옮겨 간다는 근거는 약하다.** 템플릿을 더해 생기는 차이가 seed만 바꿨을 때와 비슷한 크기다(14.9 vs 13.5).
  [template_report.md](template_report.md)의 MICE 템플릿 실험과 같은 결론이다.
- **템플릿의 입술색이 번진다.** 템플릿 입술이 분홍색이라, PT 결과는 입술이 원본보다 분홍빛이 된다(위 그림 face_000, face_022, face_062, face_078).
  `mouth` 마스크가 입술을 포함하기 때문이다.

## 4. 템플릿 + 프롬프트 조합

같은 최종 프롬프트를 `patient_only`(PO)와 `patient_tooth`(PT, 템플릿 추가)로 비교했다.
smile 75 조합에는 `upper` 템플릿, smile 100 조합에는 `both` 템플릿을 배정했다.

| 조합 | 치아 L* | b* | 신원 | jawOpen | 윗니 / 아랫니 면적 |
| --- | --- | --- | --- | --- | --- |
| PO 75 + 정렬 + 미백 | 84.8 | 0.8 | **0.92** | 0.16 | 14.9 / 9.0 |
| PT 75 + 정렬 + 미백 | 85.1 | 2.8 | 0.87 | 0.14 | 14.7 / 9.0 |
| PO 100 + 정렬 + 미백 | 84.1 | 2.2 | **0.93** | 0.20 | 17.5 / 9.9 |
| PT 100 + 정렬 + 미백 | 84.4 | 4.2 | 0.86 | 0.18 | 18.5 / **11.6** |

![최종 조합 (smile 100)](assets/smile_v3_full_combo.jpg)

- **미백·정렬 결과는 PO와 PT가 거의 같다.** 템플릿을 넣어도 더 하얗거나 더 가지런해지지 않는다(L* 차이 0.3).
- **PT는 ArcFace 신원 점수가 0.05~0.07 더 낮다** (100명 중 98명). 원인은 4.1절.
- **smile 100에서는 `both` 템플릿이 아랫니 노출을 조금 늘렸다**(아랫니 면적 9.9 → 11.6). 템플릿이 모양보다는 "얼마나 보이는지"에 영향을 주는 정도다.
- PT에서 가끔 원본의 노란 치아가 한 개 남거나 섞이는 경우가 있었다(face_075, smile 100).
- 속도: PO 1.7초, PT 2.6초 (템플릿 VAE 인코딩).

### 4.1 신원 점수 차이를 얼굴 전체로 확인

점수가 가장 많이 떨어진 5명과 중간값 근처 3명을 얼굴 전체로 비교했다. 오른쪽 열은 PT와 PO 결과가 다른 곳을 빨간색으로 표시한 것이다.

![신원 점수 하락이 가장 큰 얼굴](assets/smile_v3_identity_full_worst.jpg)
![중간값 근처 얼굴](assets/smile_v3_identity_full_typical.jpg)

| 얼굴 | PO 75 | PT 75 | PO 100 | PT 100 |
| --- | --- | --- | --- | --- |
| face_002 (하락 최대) | 0.89 | 0.74 | 0.76 | 0.70 |
| face_005 | 0.96 | 0.83 | 0.93 | 0.79 |
| face_082 | 0.98 | 0.86 | 0.94 | 0.78 |
| face_107 (중간값) | 0.97 | 0.92 | 0.97 | 0.93 |

- **PT와 PO가 다른 곳은 입술과 치아뿐이다.** 마스크 밖은 서버가 원본 픽셀로 되돌리므로, 코 위쪽(눈·코·이마)은 원본과의 평균 차이가
  0.1(0~255)로 사실상 같다.
- **얼굴 전체로 보면 PT 결과도 같은 사람으로 보인다.** 점수가 가장 많이 떨어진 face_002(0.74)도 눈·코·얼굴형·머리는 그대로이고,
  입술이 분홍빛이 되고 치아가 템플릿처럼 크고 고르게 바뀐 것이 차이다.
- 따라서 ArcFace 점수 하락은 "다른 사람이 됐다"기보다 **입 모양·입술색 변화에 ArcFace가 민감하게 반응한 것**으로 보는 게 맞다.
  다만 입술색 번짐은 실제로 원하지 않는 변화이므로, 템플릿을 쓴다면 입술을 마스크에서 빼는 비교가 필요하다(5장 3번).

2. 100 개선: 동작 지시 문장이 효과가 있었으므로 표현을 더 강하게 하거나, 입력의 jawOpen을 재서 이미 벌어진 얼굴은 건너뛴다.
3. 템플릿: 입술색 번짐을 막으려면 템플릿 편집 마스크에서 입술을 빼고(`inner_mouth`/`teeth`) 비교한다.
   모양 전이 자체는 지금 방식으로는 약하므로 우선순위를 낮춘다.
4. 이번 얼굴은 모두 합성이고 웃는 얼굴이다. 실제 환자 사진과 무표정 얼굴로 다시 확인해야 한다.
